# ИГРОТЕКА — правила для Claude Code

Интерактивный каталог реальных настольных игр для портфолио: поиск, фильтры, избранное, сравнение, светлая/тёмная тема. Статический сайт, бесплатно публикуется на GitHub Pages. Язык проекта, интерфейса, коммитов и общения с заказчиком — **русский**.

## Источники правды
- Спецификация: `docs/specs/2026-11-11-igroteka-design.md` — ЧТО делаем (§ — номера разделов).
- План: `docs/plan.md` — КАК и в каком порядке (10 этапов с чекбоксами).
- Если спецификация и план расходятся — остановись и спроси заказчика, не выбирай сам.

## Как работать
1. **Один этап за раз.** Найди в `docs/plan.md` первый этап с неотмеченными шагами и сообщи заказчику, какой этап начинаешь.
2. Выполняй шаги по порядку, отмечай `- [x]` в плане. Тесты пишутся **до** кода: тест → убедиться, что падает → реализовать → тест проходит.
3. В конце этапа — «Ритуал завершения» из плана: `npm test` → ручной чеклист → проверка отсутствия зависимостей → коммит `этап N: …` → **СТОП**.
4. Отчёт заказчику: что сделано, вывод тестов (pass/fail), что проверить руками и как, найденные проблемы. Не начинай следующий этап, пока заказчик не ответил «ок».
5. Тест падает и непонятно почему — сначала найди причину (навык superpowers:systematic-debugging), не подгоняй тест под код.
6. Ничего сверх этапа: никаких «заодно улучшу», новых функций и рефакторинга других этапов. Идеи — в отчёт.
7. **Не пушить, не создавать репозитории и не публиковать** без явного согласия заказчика. Публикацию (этап 10, шаг 7) выполняет заказчик по твоей инструкции.

## Жёсткие запреты
- **Никаких зависимостей.** Не запускать `npm install <что-либо>`, не добавлять `dependencies`/`devDependencies`, не подключать CDN, внешние шрифты, скрипты, аналитику. Только встроенные модули Node.js (для тестов и локального сервера) и API браузера. Если кажется, что без библиотеки никак, — остановись и спроси.
- **Без сервера.** Сайт должен работать как набор статических файлов из `public/` на GitHub Pages. Никаких бэкендов, баз данных, авторизации.
- **Данные отдельно от логики.** Игры — только в `public/data/games.json`. Никаких массивов игр в JS-коде (кроме фикстур в `tests/fixtures/`).
- `public/js/logic/` — чистые функции: без `document`, `window`, `localStorage`, `location`, `fetch`.
- Во фронтенде запрещены `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, строковые `setTimeout`/`setInterval`, inline-скрипты, `on*=`, `style=`, `<style>`. DOM — через `h()`/`svg()` из `public/js/ui/dom.js`, текст — через `textContent`.
- **Пути внутри `public/` только относительные** (`./…`); исключение — `public/404.html` (пути с `/igroteka/`).
- Не ослаблять CSP из §8.1 (никаких `'unsafe-inline'`, `'unsafe-eval'`, внешних доменов, снятия Trusted Types) ради того, чтобы «заработало».
- Всё, что приходит из URL, localStorage и `games.json`, проверяется по белым спискам (§8.4) — не доверять.
- Никаких ключей, токенов, паролей в репозитории.
- Не менять глобальные настройки git и системы без согласия заказчика.
- Не выдумывать факты об играх: год, авторы, игроки, время и возраст сверяются с BoardGameGeek / сайтом издателя; что не удалось проверить — сообщить. В GitHub Actions не выдумывать SHA — брать со страниц релизов.

## Команды
| Команда | Что делает |
|---|---|
| `npm test` | все тесты (`node --test "tests/**/*.test.mjs"`) |
| `node --test tests/<путь>.test.mjs` | один файл тестов |
| `npm start` | локальный сервер: `http://127.0.0.1:8080/` и `http://127.0.0.1:8080/igroteka/` (как на GitHub Pages) |

Окружение разработчика: Windows 11, Node.js 26, Git для Windows.

## Стиль кода
- ES-модули, `const` по умолчанию, функции вместо классов, где хватает функций; один файл — одна ответственность, файлы до ~250 строк.
- Имена в коде — на английском, тексты интерфейса и комментарии — на русском.
- Публичные функции модулей `logic/` — с JSDoc.
- CSS: только переменные из `public/css/tokens.css`; mobile-first; брейкпоинты 600 / 768 / 1024 / 1280.
- Доступность — часть готовности: семантика, клавиатура, `aria-*`, фокус, `prefers-reduced-motion`.
