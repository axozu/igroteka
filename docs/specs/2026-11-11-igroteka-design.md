# ИГРОТЕКА — спецификация

Дата: 2026-11-11 · Версия 3 (статический сайт с бесплатной публикацией на GitHub Pages; сервер, аккаунты и админка исключены) · Статус: на согласовании

## 1. Цель и контекст

«ИГРОТЕКА» — адаптивный интерактивный каталог настольных игр, проект для **портфолио**. Пользователь изучает реальные настольные игры, ищет и фильтрует их, сравнивает и добавляет в избранное.

Это **не лендинг и не статичная страница**: одностраничное веб-приложение с несколькими состояниями интерфейса (загрузка, ошибка, пустой результат, пустое избранное, модальное окно, сравнение, выдвижная панель).

Сайт публикуется **бесплатно на GitHub Pages** и не требует сервера. Оценивать будут и внешний вид, и качество кода, поэтому важны: чистая архитектура, отделение данных от логики, тесты, доступность, адаптивность и безопасность, доступная статическому сайту.

### Критерии успеха
1. Четыре раздела: шапка, каталог, «О проекте», подвал.
2. Не меньше 16 (цель — 20) **реальных** игр с достоверными основными фактами.
3. Данные лежат в `public/data/games.json` и не смешаны с кодом интерфейса.
4. Поиск по названию, фильтры (жанр, игроки, цена, возраст, время, сложность), сортировка, сообщение «ничего не найдено».
5. Избранное: вкладка в каталоге и выдвижная панель, сохраняется между сессиями (в браузере).
6. Подробная карточка (модалка), сравнение 2–3 игр, состояние в URL.
7. Светлая и тёмная тема с переключателем.
8. Корректная работа на 360 / 768 / 1024 / 1440 px, управление с клавиатуры.
9. **Ноль зависимостей** (в `package.json` нет `dependencies` и `devDependencies`).
10. Меры защиты из раздела 8, проверяемые автотестами.
11. Логика покрыта автотестами `node:test`, работа идёт по 10 этапам, каждый проверяется отдельно.
12. Сайт опубликован на `https://<логин>.github.io/igroteka/` по HTTPS. Публикация происходит автоматически и **только если все тесты прошли**.

### Вне рамок (не делаем)
Сервер, база данных, регистрация и вход, админка, корзина и оплата, отзывы, мультиязычность, пагинация, внешние API, аналитика и счётчики, cookie, загрузка шрифтов, сборщики и фреймворки, платный хостинг и свой домен.

## 2. Технические решения

| Решение | Выбор | Почему |
|---|---|---|
| Стек | HTML + CSS + JavaScript (ES-модули), без сборки | Без зависимостей; показывает знание основ; GitHub Pages отдаёт файлы как есть |
| Архитектура | Модули + центральное хранилище (store) с подпиской + функции отрисовки | Однонаправленный поток данных, логика тестируется без DOM |
| Данные | `public/data/games.json`, загружается через `fetch` | Данные отделены от логики; реальные состояния «загрузка/ошибка» |
| Хранение | `localStorage` (избранное, сравнение, тема) | Сервера нет |
| Тесты | `node:test` + `node:assert` | Без зависимостей; Node.js 26 уже установлен |
| Локальный запуск | `scripts/serve.mjs` — статический сервер на `node:http` | ES-модули и `fetch` не работают с `file://` |
| Хостинг | GitHub Pages, публичный репозиторий | Бесплатно; HTTPS из коробки |
| Публикация | GitHub Actions: тесты → публикация папки `public/` | Сломанный сайт не попадёт в интернет; бесплатно для публичных репозиториев |
| Шрифт | Системный стек (`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`) | Минимализм, скорость, строгий CSP |

Требование: Node.js ≥ 22 (установлен 26.13). Репозиторий должен быть **публичным**: для приватных репозиториев GitHub Pages платный.

**Правила границ:**
- `public/js/logic/` не обращается к `document`, `window`, `localStorage`, `location`, `fetch`. Всё браузерное передаётся аргументами.
- Публикуется **только** `public/`. Тесты, документы, скрипты и `package.json` на сайт не попадают.
- Все пути внутри `public/` **относительные** (`./css/…`, `./data/games.json`): на GitHub Pages сайт живёт по подпути `/igroteka/`. Единственное исключение — `404.html`: GitHub Pages отдаёт его для любого несуществующего пути любой глубины, поэтому в нём пути начинаются с `/igroteka/` (имя репозитория должно быть `igroteka`).

## 5. Состояние приложения

```js
{
  status: 'loading' | 'ready' | 'error',
  error: null | string,
  games: [], genres: [],
  query: '',
  filters: {
    genres: [],            // ИЛИ внутри группы
    players: null,         // N: min ≤ N ≤ max; 6 означает «6+» (max ≥ 6)
    priceMin: null, priceMax: null,
    age: null,             // N: game.age ≤ N
    time: [],              // 'short' | 'medium' | 'long'
    complexity: []         // 1 | 2 | 3
  },
  sort: 'rating-desc',
  view: 'all' | 'favorites',
  favorites: [],           // id в порядке добавления, максимум 100
  compare: [],             // id, максимум 3
  openGameId: null,
  drawerOpen: false,
  filtersSheetOpen: false,
  menuOpen: false,
  theme: 'system' | 'light' | 'dark'
}
```

### 5.1 Правила логики
- **Поиск.** Подстрока в `title` или `originalTitle`. Обе строки нормализуются: нижний регистр, `ё → е`, обрезка и схлопывание пробелов. Запрос обрезается до 100 символов. Пустой запрос ничего не отсекает. В интерфейсе срабатывает с задержкой 250 мс.
- **Фильтры.** Между группами — И, внутри группы — ИЛИ. Пустая группа не фильтрует.
  - Время по `playTime.max`: `short` ≤ 30, `medium` 31–60, `long` > 60.
  - Цена: `priceMin ≤ price ≤ priceMax`, любая граница может быть `null`. Если `priceMin > priceMax`, границы меняются местами. Допустимы целые 0–100000.
  - Возраст: варианты 6, 8, 10, 12, 14, 18.
  - Игроки: варианты 1, 2, 3, 4, 5, 6+.
- **Сортировка:** `rating-desc` (по умолчанию), `price-asc`, `price-desc`, `title-asc` (`localeCompare('ru')`), `year-desc`. При равенстве — по `title-asc`. Исходный массив не изменяется.
- **Конвейер:** view → поиск → фильтры → сортировка.
- **Сравнение:** до 3 игр; 4-я не добавляется, интерфейс показывает подсказку «Можно сравнить не больше 3 игр». `getBestValues` выделяет лучшее значение: рейтинг (max), цена (min), сложность (min), время (min по `playTime.max`).

### 5.2 URL
- Параметры (значения по умолчанию в адрес не пишутся): `q`, `genre`, `players`, `priceMin`, `priceMax`, `age`, `time`, `level`, `sort`, `view`, `game`.
- Ввод в поиске → `replaceState`; остальные изменения → `pushState`; `popstate` восстанавливает состояние.
- Путь страницы (`/igroteka/`) не меняется, меняется только query-строка.
- Все значения проверяются по белому списку. Некорректные молча игнорируются (§8.4).
- `queryToState(stateToQuery(s))` даёт ту же URL-часть `s`.

### 5.3 localStorage
Ключи: `igroteka:favorites`, `igroteka:compare`, `igroteka:theme`. Некорректный JSON, неверный тип, неизвестные id, превышение лимитов (100 / 3) или недоступный storage дают значение по умолчанию без ошибок. Неизвестные id отбрасываются после загрузки каталога.

## 6. Интерфейс

### 6.1 Визуальный стиль — строгий минимализм
- Светлый фон, много воздуха, тонкие границы `1px`, мягкие тени только при наведении.
- Один акцентный цвет (например, `#1F6F5C`, в тёмной теме светлее).
- Обложки — сгенерированные SVG (цвет `cover.color` + иконка + название), соотношение 4:3. Цвет задаётся атрибутом `fill`, а не атрибутом `style` (из-за CSP).
- Скругления 8–12 px, шаг отступов 4 px.
- Все цвета заданы переменными в `tokens.css`. Тёмная тема: `[data-theme="dark"]`, при `system` действует `prefers-color-scheme`.
- Контраст текста ≥ 4.5:1 в обеих темах.

### 6.2 Разделы
**Шапка** (sticky).
- Логотип «ИГРОТЕКА», навигация («Каталог», «О проекте»), поиск, кнопка темы, ♥ со счётчиком (открывает панель избранного).
- ≤ 767 px: навигация в бургер-меню, поиск переезжает в панель инструментов каталога.

**Каталог.**
- Панель инструментов: вкладки «Все игры (N)» / «Избранное (N)», «Найдено: N» (`aria-live`), сортировка, чипы активных фильтров, «Сбросить всё».
- Фильтры: ≥ 1024 px — боковая колонка; меньше — кнопка «Фильтры (k)» открывает полноэкранный лист с кнопкой «Показать N игр».
- Сетка: 1 / 2 / 3 / 4 колонки (< 600 / 600–1023 / 1024–1279 / ≥ 1280 px, с учётом колонки фильтров).
- Карточка: обложка, название и год, жанры, «игроки · время · возраст», ★ рейтинг, «≈ 3 990 ₽», ♥ (`aria-pressed`), «Сравнить». Клик открывает модалку; ♥ и «Сравнить» модалку не открывают.

**Модалка подробностей.** `<dialog>`, все поля игры, ♥, «Сравнить». Закрывается по ×, Esc и клику по фону. Фокус удерживается внутри и возвращается на карточку. В адресе `?game=id`.

**Сравнение.** Закреплённая снизу плашка «Сравнить (N) · Очистить», при N ≥ 2 открывает `<dialog>` с таблицей и выделенными лучшими значениями. На телефоне горизонтальная прокрутка, первая колонка закреплена.

**Панель избранного.** Выезжает справа (на телефоне — на всю ширину). Список (мини-обложка, название, цена, ×), итог «N игр · ≈ сумма ₽», «Показать в каталоге», пустое состояние. Esc и клик по фону закрывают панель.

**О проекте.** Текст, три преимущества, статистика из `getCatalogStats` (игр, жанров, средний рейтинг, диапазон цен).

**Подвал.** «ИГРОТЕКА © <текущий год>», навигация, «Цены ориентировочные, данные приведены для демонстрации», ссылка на репозиторий GitHub (`rel="noopener noreferrer"`).

**404.html.** «Страница не найдена» + ссылка «В каталог» (относительная). Тот же CSP и стили.

### 6.3 Состояния интерфейса

| Состояние | Что видит пользователь |
|---|---|
| Загрузка | 8 скелетонов карточек |
| Ошибка загрузки или проверки данных | «Не удалось загрузить каталог» + «Повторить» |
| Ничего не найдено | «По запросу «…» ничего не найдено» / «Под выбранные фильтры игр нет» + «Сбросить поиск» / «Сбросить фильтры» |
| Избранное пусто | «Вы пока ничего не добавили в избранное» + «Перейти в каталог» |
| Модалка, сравнение, панель, лист фильтров, бургер | Соответствующие окна |
| Уведомление (toast) | Например, «Можно сравнить не больше 3 игр» |

### 6.4 Доступность
Семантические теги, работа с клавиатуры, `:focus-visible`, `aria-live`, `aria-pressed`, `aria-expanded`, удержание фокуса в модалках, Esc закрывает, `prefers-reduced-motion`, у обложек `role="img"` + `aria-label`.

## 7. Поток данных

```
main.js
  ├─ createStore(initial ← queryToState(location.search) + localStorage)
  ├─ loadCatalog(): fetch('./data/games.json') → validateCatalog → setState({status:'ready', ...})
  │                                                └─ ошибка → setState({status:'error'})
  ├─ store.subscribe(render)    // ui/*
  ├─ startUrlSync(store)        // url-sync.js
  ├─ store.subscribe(persist)   // localStorage
  └─ ui/* навешивают обработчики (делегированием) → store.setState(...)
```

Отрисовка идемпотентна. Сетка перерисовывается только при изменении списка видимых игр. Поля ввода не пересоздаются.

## 8. Безопасность (то, что доступно статическому сайту)

У сайта нет сервера, базы, аккаунтов и секретов, поэтому взламывать на нём серверную часть нечего. Главные риски — XSS (внедрение чужого кода в страницу), подмена данных, утечка ключей в репозиторий и компрометация процесса публикации. Меры:

### 8.1 Content Security Policy
Тег `<meta http-equiv="Content-Security-Policy">` — **первый** элемент `<head>` в `index.html` и `404.html`:

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self';
connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none';
require-trusted-types-for 'script'; trusted-types 'none'
```

(`upgrade-insecure-requests` не используется: он мешает локальному запуску по `http://127.0.0.1`, а на GitHub Pages HTTPS и так обязателен, все ресурсы — относительные.)

- Никаких inline-скриптов, обработчиков `on*=` и атрибутов `style=`; никаких внешних доменов.
- `require-trusted-types-for 'script'` + `trusted-types 'none'`: в Chrome и Edge браузер сам **запрещает** опасные вставки HTML вроде `innerHTML = строка`. Это второй уровень защиты поверх правил кода.
- Ограничение: GitHub Pages не позволяет задавать HTTP-заголовки, а в `<meta>` не работают `frame-ancestors` (защита от встраивания во фрейм) и `X-Frame-Options`. Риск низкий: на сайте нет действий, которые можно навязать через фрейм. Это фиксируется в `SECURITY.md`.

### 8.2 Прочие мета-теги и ссылки
- `<meta name="referrer" content="strict-origin-when-cross-origin">`.
- Все внешние ссылки: `target="_blank" rel="noopener noreferrer"`.
- Нет cookie, аналитики, трекеров и запросов к сторонним сайтам → сайт ничего не знает о посетителе, баннер согласия не нужен.

### 8.3 XSS в коде
- Данные вставляются в страницу только через `textContent`, `setAttribute` (не для `on*` и не для `href` со схемами кроме `http(s)`) или `svg`/`h()`-помощники.
- Запрещены `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, строковые `setTimeout`/`setInterval`. Это проверяет тест-сканер `tests/security/no-dangerous-dom.test.mjs`, который действует **с этапа 5**.
- Сканер HTML-файлов: нет inline-скриптов, `on*=`, `style=`, `<style>`, внешних `src`/`href` (кроме ссылки на GitHub в подвале).

### 8.4 Проверка всех входных данных
Источники данных для сайта: адресная строка, localStorage и `games.json`. Всем им не доверяем:
- **URL:** каждый параметр проверяется по белому списку (§5.2): числа — диапазоны, жанры и id игр — только существующие, `sort`/`view` — только известные значения, `q` ≤ 100 символов. Мусор игнорируется.
- **localStorage:** `readJSON` с проверкой типа и лимитов, никогда не бросает исключений.
- **games.json:** `validateCatalog` перед отрисовкой; лишние поля, неверные типы и длины → состояние ошибки.

### 8.5 HTTPS
- GitHub Pages отдаёт сайт по HTTPS; в настройках включается **Enforce HTTPS** (http перенаправляется на https).
- Домен `github.io` входит в HSTS preload-список браузеров — защищённое соединение принудительно.

### 8.6 Секреты и репозиторий
- В проекте **нет и не должно быть** ключей, токенов и паролей. Тест-сканер `tests/security/no-secrets.test.mjs` ищет похожие на ключи строки в файлах, отслеживаемых git.
- На GitHub (бесплатно для публичных репозиториев) включаются **Secret scanning** и **Push protection**: GitHub блокирует push, если в нём найден ключ.
- `.gitignore`: `.env`, `node_modules/`, логи, системные файлы.

### 8.7 Безопасная публикация (GitHub Actions)
- Workflow `.github/workflows/pages.yml`: задача `test` (`npm test`) → задача `deploy` (`needs: test`), публикуется только папка `public/`.
- Минимальные права: на уровне workflow `permissions: contents: read`; задаче deploy — только `pages: write` и `id-token: write`.
- Официальные actions (`actions/checkout`, `actions/setup-node`, `actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`) закреплены по **полному SHA коммита** с комментарием версии — защита от подмены action.
- Запуск: `push` в `main` и вручную (`workflow_dispatch`). Для pull request — только тесты, без публикации.
- `concurrency: pages` — две публикации не идут одновременно.
- Рекомендации для аккаунта (выполняет заказчик, описано в `SECURITY.md`): 2FA на аккаунте GitHub; защита ветки `main` (обязательное прохождение тестов перед слиянием, запрет force-push).

### 8.8 Цепочка поставок
Ноль зависимостей: через пакеты npm атаковать нечего, `npm install` не нужен. Единственный внешний код — официальные GitHub Actions, закреплённые по SHA (§8.7).

### 8.9 Документ `SECURITY.md`
Перечень мер, что они закрывают, известные ограничения (§8.1) и как сообщить о проблеме.

## 9. Тестирование
- `npm test` → `node --test "tests/**/*.test.mjs"`. Тесты покрывают **всё** в `public/js/logic/`, проверяют `games.json`, CSP и сканеры кода.
- UI проверяется по ручным чеклистам из `docs/plan.md` на ширинах 360 / 768 / 1024 / 1440 в обеих темах.
- Тесты автоматически запускаются в GitHub Actions при каждом push; публикация только при зелёных тестах.
- Финал: Lighthouse ≥ 90 по всем четырём категориям на опубликованном сайте; в консоли нет ошибок и нарушений CSP.
